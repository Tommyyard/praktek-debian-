Setup GNS3: Debian Router + DHCP Server + Web Server + WordPress

Alur lengkap: bangun topologi NAT–Debian–Switch–PC Windows, konfigurasi dua interface (DHCP di sisi cloud, static di sisi client), Debian aktif jadi DHCP server untuk LAN, lanjut dipasangi Apache + MariaDB + PHP, sampai WordPress ter-install dan ada konten pertama yang bisa diakses lewat browser PC Windows. Tiap perintah disertai fungsi dan contoh output-nya pada momen dijalankan.

jalur DHCP (dari cloud ke ens4) jalur DHCP server (ens5 ke LAN)

Bagian 1 — Topologi & Interface Dasar

Membangun topologi di GNS3 dan mengaktifkan dua interface Debian.

1

Buat topologi di GNS3

Tarik 4 node: NAT (Cloud), Debian (server), Switch, PC Windows.

2

Rencanakan 2 interface di Debian

ens4 menghadap Cloud/NAT (IP otomatis via DHCP), ens5 menghadap Switch/klien (nantinya jadi DHCP server untuk LAN).

3

Hubungkan NAT (Cloud) ke PC Windows — sementara

Sambungkan dulu Cloud langsung ke PC Windows untuk keperluan setup awal (download Putty). Diputus lagi di langkah 6.

4

Set PC Windows ke DHCP

Buka Network Adapter Settings → Obtain an IP address automatically.

5

Download & install Putty

Selesaikan instalasi Putty di PC Windows — dipakai nanti untuk SSH ke Debian. IP static 192.168.1.10 boleh diisi sementara di sini.

6

Ubah ulang pengkabelan di GNS3

Putuskan kabel Cloud–Windows. Sambungkan sesuai topologi final:

Cloud (NAT) ── Debian(ens4) ... Debian(ens5) ── Switch ── PC Windows
7

Login ke Debian

Masukkan username dan password Debian di console GNS3.

8

Masuk mode super user

sudo su
Fungsi: pindah dari user biasa ke shell root, supaya bisa edit file konfigurasi sistem dan restart service tanpa dibatasi permission.
Output: prompt terminal berubah dari $ jadi # — itu tandanya sudah jadi root.
9

Cek interface yang terdeteksi

ip a
Fungsi: menampilkan semua interface network yang dikenali sistem beserta status dan IP address-nya.
Output: tiap interface muncul sebagai blok bernomor, contoh 2: ens4: <UP,LOWER_UP> ... inet 10.0.3.15/24. Kalau baris inet (IPv4) belum ada dan cuma ada inet6 (fe80::...), berarti interface itu belum dapat IP.
10

Buka file konfigurasi interface

nano /etc/network/interfaces
Fungsi: membuka file konfigurasi network utama Debian di editor nano, tempat interface didaftarkan dan diberi mode (dhcp/static).
Output: bukan output teks — yang muncul adalah tampilan editor nano menampilkan isi file tersebut, siap diedit.
11

Aktifkan konfigurasi ens4 & ens5

Maksud "hapus 6 tanda pager" di catatan aslinya: pada template bawaan, baris auto/iface untuk kedua interface biasanya dikomentari dengan tanda # (pagar) — 3 baris untuk ens4, 3 untuk ens5, total 6. Hapus semua tanda # itu supaya baris-baris aktif.

Sebelum (contoh template)

# auto ens4
# iface ens4 inet dhcp
#
# auto ens5
# iface ens5 inet static
#     address 192.168.1.1

Sesudah (aktif)

auto lo
iface lo inet loopback

auto ens4
iface ens4 inet dhcp

auto ens5
iface ens5 inet static
    address 192.168.1.1
    netmask 255.255.255.0
Fungsi auto ens4: menandai interface diaktifkan otomatis saat boot / saat networking di-restart.
Fungsi iface ens4 inet dhcp: minta IP otomatis dari DHCP server di jalur cloud/NAT.
Fungsi iface ens5 inet static + address/netmask: pasang IP tetap 192.168.1.1/24 di ens5 — ini nanti jadi gateway sekaligus alamat DHCP server untuk LAN.
Sesuaikan: IP 192.168.1.1 cuma contoh gateway untuk LAN 192.168.1.0/24. Ganti kalau skema IP kamu beda. Simpan Ctrl+O → Enter, keluar Ctrl+X.
12

Restart service networking

systemctl restart networking
systemctl status networking -l
Fungsi restart: menerapkan ulang isi /etc/network/interfaces yang baru diedit ke seluruh interface.
Fungsi status: mengecek apakah service networking berhasil jalan atau gagal.
Output sukses: Active: active (exited). Output gagal: Active: failed disertai baris error — biasanya karena typo syntax di file interfaces.
12b

Set hostname & edit /etc/hosts

Cek dulu hostname Debian saat ini (defaultnya biasanya debian):

hostname

Kalau mau diganti jadi nama yang lebih jelas, edit filenya (isi cukup satu kata, tanpa spasi, misal debian-server):

sudo nano /etc/hostname

Lalu edit /etc/hosts:

sudo nano /etc/hosts

Format tiap baris: IP   nama-domain   nama-host (dipisah spasi/tab, tanpa prefix /24 — /etc/hosts memang tidak pernah pakai notasi CIDR sama sekali).

Isi default

127.0.0.1       localhost
127.0.1.1       debian

Ditambah (2 baris baru)

127.0.0.1       localhost
127.0.1.1       skadika.net       debian-server
192.168.1.1     www.skadika.net skadika.net
Fungsi baris 127.0.1.1 ...: ini konvensi baku Debian (bukan 127.0.0.1 biasa) — dipasangkan ke domain & hostname supaya perintah seperti sudo atau hostname -f bisa resolve nama server ini sendiri tanpa perlu nanya DNS/BIND9. Baris ini cuma dipakai internal server, tidak ada hubungannya dengan client lain di LAN.
Fungsi baris 192.168.1.1 www.skadika.net skadika.net: ini tambahan di luar pola bawaan buku — supaya Debian server itu sendiri juga bisa resolve www.skadika.net ke IP LAN-nya lewat /etc/hosts duluan, sebelum sempat nanya BIND9. Berguna kalau mau tes curl www.skadika.net langsung dari console Debian di Bagian 4 tanpa bergantung ke DNS server yang sama-sama jalan di mesin ini.
Kenapa dua-duanya boleh beda IP: baris pertama (127.0.1.1) untuk resolusi hostname internal, baris kedua (192.168.1.1) untuk resolusi domain LAN — beda tujuan, tidak konflik walau sama-sama merujuk domain skadika.net.
Output: tidak ada output CLI; berlaku begitu file disimpan, tidak perlu restart service apa pun.
Baris 192.168.1.1 www.skadika.net skadika.net di sini hanya berlaku untuk Debian server itu sendiri — PC Windows dan client lain di LAN tetap wajib resolve lewat BIND9 (Bagian 3), karena mereka tidak baca /etc/hosts punya Debian.
13

Update repo Debian

sudo apt update
Fungsi: mengecek ulang daftar paket terbaru dari repository Debian (belum menginstall apa pun, cuma refresh index lokal).
Output sukses: deretan baris Get:1 http://deb.debian.org/debian bookworm InRelease ... diakhiri Reading package lists... Done.
14

Kalau ada error saat update

Lihat Bagian 9 — Troubleshooting apt update di bawah — biasanya penyebabnya ens4 belum dapat IP dari DHCP (routing, bukan DNS).

Bagian 2 — Jadikan Debian sebagai DHCP Server (ens5)

Lanjutan dari Bagian 1: sekarang ens5 tidak cuma dikasih IP static, tapi Debian juga membagikan IP otomatis ke semua client di LAN (Switch → PC Windows) lewat isc-dhcp-server.

15

Install paket DHCP server

sudo apt install isc-dhcp-server
Fungsi: menginstall service isc-dhcp-server — daemon yang akan menjawab request DHCP dari client dan membagikan IP.
Output: proses download & install paket. Di akhir mungkin ada warning isc-dhcp-server.service failed — wajar di titik ini karena dhcpd.conf belum diisi dan interface belum ditentukan (diperbaiki di langkah 16–17).
16

Tentukan interface yang dilayani

nano /etc/default/isc-dhcp-server
INTERFACESv4="ens5"
Fungsi: memberi tahu service, interface mana yang harus "didengarkan" untuk request DHCP broadcast dari client — kalau kosong atau salah nama interface, service gagal start (persis error systemctl restart isc-dhcp-server yang muncul di awal).
Output: tidak ada output langsung; verifikasi dengan cat /etc/default/isc-dhcp-server setelah disimpan.
17

Isi konfigurasi subnet di dhcpd.conf

nano /etc/dhcp/dhcpd.conf
subnet 192.168.1.0 netmask 255.255.255.0 {
    range 192.168.1.100 192.168.1.200;
    option routers 192.168.1.1;
    option domain-name-servers 8.8.8.8, 8.8.4.4;
}
subnet ... netmask ...: jaringan yang dilayani DHCP server ini — wajib cocok dengan network address IP static ens5 (192.168.1.0/24).
range: rentang IP yang boleh dibagikan otomatis ke client. Sengaja mulai dari .100 supaya tidak tabrakan dengan IP static (misalnya ens5 sendiri di .1).
option routers: IP gateway yang diberitahukan ke client — di sini alamat ens5 Debian sendiri.
option domain-name-servers: DNS server yang dipakai client untuk resolve nama domain.
Output: tidak ada output CLI — hasilnya baru kelihatan saat restart service di langkah 18.
18

Restart & cek service DHCP

systemctl restart isc-dhcp-server
systemctl status isc-dhcp-server -l
Fungsi: menerapkan config baru dari langkah 16–17, lalu mengecek apakah service benar-benar jalan.
Output sukses: Active: active (running) disertai log Listening on LPF/ens5/....
Output gagal (ini skenario di awal chat): Job for isc-dhcp-server.service failed....
Kalau gagal, jangan asal restart ulang — cek dulu baris mana di dhcpd.conf yang error:
dhcpd -t -cf /etc/dhcp/dhcpd.conf
Fungsi: menjalankan dhcpd dalam mode test (-t) terhadap file config tertentu (-cf) — tidak benar-benar menyalakan service, cuma mengecek syntax-nya valid atau tidak.
Output kalau ada syntax error (contoh — lupa titik-koma):
Internet Systems Consortium DHCP Server 4.4.1
Copyright 2004-2018 Internet Systems Consortium.
All rights reserved.
For info, please visit https://www.isc.org/software/dhcp/

/etc/dhcp/dhcpd.conf line 15: semicolon expected.
}
^
Configuration file errors encountered -- exiting
Maksud output di atas:
• line 15 → baris ke-15 di dhcpd.conf yang bermasalah, langsung buka nano /etc/dhcp/dhcpd.conf lalu lompat ke baris itu (di nano bisa pakai Ctrl+_ lalu ketik nomor barisnya).
• semicolon expected → jenis errornya: dhcpd nunggu tanda titik-koma ; di akhir baris tapi tidak ketemu. Error umum lain: Expecting numeric value (salah format IP/angka), atau unexpected end of file (ada kurung { } yang tidak menutup).
• Simbol ^ di bawah baris } → penanda posisi kira-kira di mana parser berhenti, biasanya pas di baris setelah baris yang sebenarnya kurang titik-koma.
• Configuration file errors encountered -- exiting → kesimpulan: config tidak valid, dan ini sebabnya systemctl restart isc-dhcp-server di langkah sebelumnya gagal.
Output kalau syntax OK: cuma banner versi (4 baris pertama di atas) tanpa baris line ... error apa pun, lalu keluar normal — tandanya config sudah siap dipakai, lanjut systemctl restart isc-dhcp-server lagi.
19

Balik PC Windows ke mode DHCP

Buka lagi Network Adapter Settings di PC Windows, ubah dari static 192.168.1.10 kembali ke Obtain an IP address automatically.

ipconfig /release
ipconfig /renew
Fungsi /release: melepas IP yang sedang dipakai adapter.
Fungsi /renew: minta ulang IP baru ke DHCP server yang aktif di jaringan — sekarang harusnya dijawab oleh Debian, bukan manual lagi.
Output: PC Windows dapat IP baru di rentang 192.168.1.100–200, dengan default gateway 192.168.1.1.
20

Pantau proses DHCP dari sisi Debian

journalctl -u isc-dhcp-server -f
Fungsi: memonitor log service DHCP secara real-time, supaya kelihatan proses request-response saat PC Windows minta IP.
Output berhasil:
DHCPDISCOVER from <mac-address> via ens5
DHCPOFFER on 192.168.1.100 to <mac-address> via ens5
DHCPACK on 192.168.1.100 to <mac-address> via ens5

Kalau urutan DISCOVER → OFFER → ACK ini muncul, DHCP server sudah jalan dengan benar. Tekan Ctrl+C untuk keluar dari mode monitor.

Bagian 3 — Pasang DNS Server (BIND9)

Sebelum masuk ke web server, Debian yang sama dijadikan DNS server lokal dulu lewat bind9. Tujuannya: nanti situs WordPress bisa diakses pakai nama domain (misalnya www.skadika.net), bukan cuma ketik IP 192.168.1.1 mentah-mentah dari browser.

21

Install BIND9

sudo apt install bind9 bind9utils bind9-doc -y
Fungsi bind9: software DNS server-nya sendiri — nanti menjawab pertanyaan "IP dari domain X berapa?" dari client di LAN.
Fungsi bind9utils: kumpulan tool bantu buat cek config (named-checkconf, named-checkzone) sebelum service direstart — dipakai di langkah 26.
Fungsi bind9-doc: dokumentasi offline, opsional tapi ringan jadi disertakan.
Output: proses install paket, service named/bind9 otomatis aktif di akhir instalasi (BIND9 memang jalan dengan nama proses named).
22

Cek service aktif

systemctl status bind9 -l
Fungsi: memastikan BIND9 sudah jalan sebelum lanjut konfigurasi zona.
Output sukses: Active: active (running) disertai log Listening on ... port 53 — port 53 memang port standar protokol DNS.
23

Aktifkan forwarders (buat domain publik tetap jalan)

sudo nano /etc/bind/named.conf.options
Fungsi: BIND9 nanti cuma tahu domain lokal (skadika.net) yang didaftarkan sendiri di langkah 24. Supaya domain publik lain (kalau lab-nya kebetulan tersambung internet) tetap bisa di-resolve, BIND9 perlu "meneruskan" pertanyaan itu ke DNS publik.

Sebelum (default, dikomentari)

// forwarders {
        //   0.0.0.0;
        // };

        dnssec-validation auto;

Sesudah (diaktifkan)

        forwarders {
            8.8.8.8;
            8.8.4.4;
        };

        dnssec-validation auto;
Output: tidak ada output CLI — baru diverifikasi lewat named-checkconf di langkah 26.
24

Daftarkan zona domain lokal (forward & reverse)

sudo nano /etc/bind/named.conf.local

Tambahkan dua blok berikut di baris paling bawah — satu untuk forward zone (nama → IP), satu untuk reverse zone (IP → nama):

zone "skadika.net" {
    type master;
    file "/etc/bind/db.skadika.net";
};

zone "1.168.192.in-addr.arpa" {
    type master;
    file "/etc/bind/db.192";
};
Fungsi zone "skadika.net": mendaftarkan domain skadika.net sebagai domain yang "dimiliki" & dijawab langsung oleh server ini (bukan diteruskan ke DNS lain) — ini forward zone.
Fungsi zone "1.168.192.in-addr.arpa": ini reverse zone, kebalikan dari forward — dipakai untuk pertanyaan "IP 192.168.1.x itu nama domainnya apa?". Nama zonanya oktet IP network yang dibalik urutan (192.168.1 → 1.168.192) ditambah akhiran baku .in-addr.arpa.
Fungsi type master: server ini adalah sumber data utama (bukan sekadar cache/salinan) untuk kedua zona ini.
Fungsi file: menunjuk ke file zona yang isinya daftar record — forward zone (db.skadika.net) dibuat di langkah 25, reverse zone (db.192) dibuat di langkah 25b.
Output: tidak ada output CLI; kedua file ini baru dipakai saat BIND9 direstart.
Kenapa dua-duanya sekaligus? Supaya satu kali edit named.conf.local, lalu baru bikin isi filenya belakangan (langkah 25 & 25b) — daripada bolak-balik buka file yang sama dua kali.
25

Buat file zona & isi record

sudo cp /etc/bind/db.local /etc/bind/db.skadika.net
sudo nano /etc/bind/db.skadika.net
Fungsi cp db.local ...: BIND9 sudah menyediakan template zona dasar (db.local) — lebih aman disalin dulu daripada nulis dari nol, tinggal disesuaikan.

Sebelum (template db.local)

$TTL    604800
@       IN      SOA     localhost. root.localhost. (
                              2         ; Serial
                         604800         ; Refresh
                          86400         ; Retry
                        2419200         ; Expire
                         604800 )       ; Negative Cache TTL
;
@       IN      NS      localhost.
@       IN      A       127.0.0.1
@       IN      AAAA    ::1

Sesudah (disesuaikan)

$TTL    604800
@       IN      SOA     ns.skadika.net. admin.skadika.net. (
                              3         ; Serial (naikkan tiap edit)
                         604800         ; Refresh
                          86400         ; Retry
                        2419200         ; Expire
                         604800 )       ; Negative Cache TTL
;
@       IN      NS      ns.skadika.net.
ns      IN      A       192.168.1.1
www     IN      A       192.168.1.1
@       IN      A       192.168.1.1
Fungsi SOA (Start of Authority): catatan administratif zona — siapa nameserver utamanya, email admin (titik menggantikan @), dan nomor Serial yang wajib dinaikkan tiap kali file ini diedit supaya perubahan dianggap "versi baru".
Fungsi baris NS: menunjuk nameserver resmi untuk domain ini.
Fungsi baris A: pemetaan nama host → IP. Baris www IN A 192.168.1.1 inilah yang bikin www.skadika.net nanti mengarah ke web server di Bagian 4. Baris @ IN A membuat domain tanpa www (skadika.net polos) juga mengarah ke IP yang sama.
Jangan lupa titik (.) di akhir nama domain pada baris SOA dan NS (misal ns.skadika.net.) — di syntax zona BIND, titik di akhir berarti "nama lengkap/absolut". Lupa titik ini adalah typo tersering.
25b

Buat file zona reverse (PTR) & isi record

sudo cp /etc/bind/db.127 /etc/bind/db.192
sudo nano /etc/bind/db.192
Fungsi cp db.127 ...: sama seperti langkah 25 tadi (copy template daripada nulis dari nol) — bedanya kali ini templatenya db.127, template reverse bawaan BIND9 untuk loopback (127.in-addr.arpa), lebih cocok dijadikan dasar reverse zone daripada db.local yang formatnya forward.

Sebelum (template db.127)

$TTL    604800
@       IN      SOA     localhost. root.localhost. (
                              1         ; Serial
                         604800         ; Refresh
                          86400         ; Retry
                        2419200         ; Expire
                         604800 )       ; Negative Cache TTL
;
@       IN      NS      localhost.
1.0.0   IN      PTR     localhost.

Sesudah (disesuaikan)

$TTL    604800
@       IN      SOA     ns.skadika.net. admin.skadika.net. (
                              2         ; Serial (naikkan tiap edit)
                         604800         ; Refresh
                          86400         ; Retry
                        2419200         ; Expire
                         604800 )       ; Negative Cache TTL
;
@       IN      NS      ns.skadika.net.
1       IN      PTR     ns.skadika.net.
Fungsi baris PTR: kebalikan dari record A di forward zone — memetakan IP → nama domain. Baris 1 IN PTR ns.skadika.net. artinya "IP dengan oktet terakhir 1 di jaringan 192.168.1.0/24 (jadi 192.168.1.1) adalah ns.skadika.net" — oktet terakhir saja yang ditulis di sini karena tiga oktet pertama (1.168.192) sudah dinyatakan lewat nama zona di named.conf.local (langkah 24).
Kenapa nomor Serial mulai dari 2, bukan 1 lagi: supaya konsisten dengan forward zone di langkah 25 yang juga sudah dinaikkan dari template awalnya — bukan aturan wajib, boleh mulai dari angka berapa saja asal konsisten dinaikkan tiap edit berikutnya.
Jangan tertukar dengan forward zone: file ini isinya cuma daftar PTR (IP → nama), bukan A (nama → IP). Kalau cuma ada satu host di LAN yang perlu di-reverse (yaitu ens5 sendiri di 192.168.1.1), satu baris PTR ini sudah cukup — tidak perlu baris PTR terpisah untuk www, karena www memang mengarah ke IP yang sama.
26

Cek syntax config & zona sebelum restart

named-checkconf
named-checkzone skadika.net /etc/bind/db.skadika.net
named-checkzone 1.168.192.in-addr.arpa /etc/bind/db.192
Fungsi named-checkconf: mengecek syntax named.conf.options & named.conf.local — mirip peran dhcpd -t di Bagian 2 (langkah 18).
Fungsi named-checkzone: khusus mengecek isi file zona — baris pertama cek forward zone (langkah 25), baris kedua cek reverse zone (langkah 25b). Nama zona yang diketik harus persis sama dengan yang didaftarkan di named.conf.local (langkah 24), bukan nama filenya.
Output kalau OK: named-checkconf diam saja tanpa output (tanda sukses). Tiap named-checkzone menampilkan loaded serial ... lalu baris OK — jadi kalau dua zona, harus muncul dua baris OK.
Output kalau ada error: muncul pesan spesifik disertai nomor baris, contoh dns_master_load: /etc/bind/db.skadika.net:9: unknown RR type — tandanya ada typo di tipe record (SOA/NS/A/PTR) atau titik-koma yang salah tempat.
27

Restart & tes BIND9 dari Debian sendiri

sudo systemctl restart bind9
systemctl status bind9 -l
Kalau muncul command not found saat pakai dig: di Debian versi baru, dig bukan bagian dari paket bind9 lagi — harus diinstall terpisah sebagai paket client: 
sudo apt install dnsutils -y
Kalau nama paket itu juga tidak ketemu (di Debian 11 ke atas namanya berubah), coba: 
sudo apt install bind9-dnsutils -y
dig @localhost www.skadika.net
Fungsi dig: tool query DNS — @localhost artinya "tanya ke server DNS di mesin ini sendiri", diikuti nama domain yang mau dicek. Ini tes forward (nama → IP).
Kenapa paket ini terpisah dari bind9: bind9 cuma berisi komponen server (named), sedangkan dig/nslookup adalah tool client buat nge-test — dua fungsi beda paket, meskipun sama-sama "punya" tim BIND.
Output sukses, di bagian ANSWER SECTION:
;; ANSWER SECTION:
www.skadika.net.          604800  IN      A       192.168.1.1

Kalau baris ini muncul, BIND9 sudah benar menjawab domain lokal dengan IP yang tepat.

dig -x 192.168.1.1 @localhost
Fungsi -x: mode reverse lookup — tanya "IP ini domainnya apa?" (kebalikan dari tes sebelumnya). dig otomatis membalik oktet IP jadi format in-addr.arpa di belakang layar, tidak perlu diketik manual.
Output sukses, di bagian ANSWER SECTION:
;; ANSWER SECTION:
1.1.168.192.in-addr.arpa. 604800 IN PTR ns.skadika.net.

Kalau baris ini muncul, reverse zone (langkah 24 & 25b) sudah benar — forward dan reverse dua-duanya sekarang jalan.

28

Arahkan DHCP supaya client pakai DNS lokal ini

sudo nano /etc/dhcp/dhcpd.conf

Ubah baris option domain-name-servers yang sudah dibuat di Bagian 2 (langkah 17), dan tambahkan option domain-name:

Sebelum (Bagian 2, langkah 17)

subnet 192.168.1.0 netmask 255.255.255.0 {
    range 192.168.1.100 192.168.1.200;
    option routers 192.168.1.1;
    option domain-name-servers 8.8.8.8, 8.8.4.4;
}

Sesudah (pakai DNS lokal)

subnet 192.168.1.0 netmask 255.255.255.0 {
    range 192.168.1.100 192.168.1.200;
    option routers 192.168.1.1;
    option domain-name-servers 192.168.1.1;
    option domain-name "skadika.net";
}
Fungsi: tanpa perubahan ini, PC Windows tetap pakai 8.8.8.8 sebagai DNS-nya — jadi tidak akan pernah tahu www.skadika.net itu domain apa (karena domain itu cuma dikenal BIND9 lokal, bukan Google). Dengan diarahkan ke 192.168.1.1, semua pertanyaan domain dari client lewat BIND9 dulu — domain lokal dijawab langsung, domain publik diteruskan lewat forwarders (langkah 23).
sudo systemctl restart isc-dhcp-server

Terapkan perubahan config DHCP.

29

Refresh IP di PC Windows

ipconfig /release
ipconfig /renew
ipconfig /all
Fungsi: sama seperti di Bagian 2 (langkah 19) — minta ulang konfigurasi DHCP dari awal, supaya setting DNS baru dari langkah 28 ikut terbawa. /all menampilkan detail lengkap termasuk baris DNS.
Output yang dicek: baris DNS Servers di hasil ipconfig /all sekarang harus menunjuk ke 192.168.1.1, bukan 8.8.8.8 lagi.
30

Tes resolusi domain dari PC Windows

nslookup www.skadika.net
ping www.skadika.net
Fungsi nslookup: versi Windows dari dig — tanya ke DNS server yang aktif (harusnya sekarang otomatis ke 192.168.1.1) untuk resolve nama domain.
Output sukses: nslookup menampilkan Server: 192.168.1.1 lalu Name: www.skadika.net, Address: 192.168.1.1. ping membalas dari 192.168.1.1, bukan "could not find host".
Mulai dari sini, web server yang dipasang di Bagian 4 dan seterusnya bisa langsung diakses dari browser PC Windows pakai http://www.skadika.net, sebagai ganti mengetik IP 192.168.1.1 mentah-mentah.

Checklist Cepat — DNS (BIND9)

  • dig: command not found → belum ada paket clientnya, install dulu: sudo apt install dnsutils -y (atau bind9-dnsutils di Debian 11+)
  • systemctl status bind9 harus active (running), listening di port 53
  • named-checkconf & named-checkzone untuk kedua zona (forward db.skadika.net dan reverse db.192) — semuanya harus bersih dari error sebelum restart
  • Baris SOA/NS di file zona wajib diakhiri titik (ns.skadika.net.) — lupa titik adalah penyebab error tersering, berlaku di forward maupun reverse zone
  • Nomor Serial di SOA dinaikkan tiap kali file zona diedit ulang — forward & reverse dihitung terpisah
  • dig -x 192.168.1.1 @localhost gagal/kosong → cek lagi blok zona 1.168.192.in-addr.arpa di named.conf.local (langkah 24) dan isi db.192 (langkah 25b)
  • ipconfig /all di PC Windows — baris DNS Servers harus 192.168.1.1, bukan 8.8.8.8
  • nslookup www.skadika.net gagal → cek lagi option domain-name-servers di dhcpd.conf (langkah 28) sudah diubah & isc-dhcp-server sudah direstart
Titik pijak: mulai bagian ini, Debian yang sama (yang tadi sudah jadi router + DHCP server + DNS server) sekarang juga dipakai sebagai web server. Tidak perlu node baru di GNS3 — semua perintah di bawah tetap dijalankan di console Debian yang sama, dan hasilnya nanti diakses dari browser di PC Windows lewat http://www.skadika.net atau IP 192.168.1.1 (alamat ens5).

Fungsi chown -R www-data:www-data: www-data adalah user sistem yang dipakai Apache buat jalan. Dengan menjadikan dia pemilik seluruh folder, WordPress jadi bisa menulis file sendiri (upload gambar, install plugin/theme, update otomatis) tanpa error "permission denied".

Bagian 9 — Troubleshooting: Error apt update

Dipakai kalau kena error di langkah 14 (Bagian 1) — error apt update yang keliatannya soal DNS padahal biasanya soal routing/DHCP.

Gejala

Saat menjalankan apt update, muncul:

Temporary failure resolving 'deb.debian.org'

Dan saat ping 8.8.8.8:

ping: connect: Network is unreachable
Jangan tertipu: kata "resolving" di pesan error itu kelihatan kayak masalah DNS, padahal biasanya bukan. Ikuti langkah di bawah untuk cek akar masalah sebenarnya.

Jalur Cepat (Coba Ini Dulu)

Sebelum masuk ke diagnosa detail di bawah, sering kali cukup dengan loop singkat ini — terutama kalau penyebabnya cuma typo pas edit /etc/network/interfaces:

1. Cek ulang status interface
ip a
Fungsi: lihat lagi apakah ens4 (dan ens5) sudah punya IPv4 yang benar setelah edit terakhir.
Output: kalau ens4 masih cuma inet6 fe80::... tanpa baris inet, berarti config belum kepasang dengan benar — lanjut ke langkah 2.
2. Kalau masih salah, perbaiki lagi confignya
nano /etc/network/interfaces
Fungsi: buka lagi file yang sama, cek baris auto/iface — typo yang paling sering: lupa hapus tanda #, salah nama interface (ens4 vs ens5 tertukar), atau baris address/netmask ke-indent tidak konsisten.
3. Restart networking
systemctl restart networking
Fungsi: terapkan ulang perbaikan tadi.
Output: kalau tidak ada error yang tampil, config sudah kebaca dengan benar. Cek lagi dengan systemctl status networking -l kalau mau lebih yakin.
4. Coba apt update lagi
apt update
Fungsi: tes ulang — kalau loop 1–3 sudah membetulkan interface, ini biasanya langsung berhasil tanpa perlu ifdown/ifup atau diagnosa lebih dalam.
Kalau setelah loop ini masih gagal (interface sudah benar tapi tetap "Network is unreachable" atau "No DHCPOFFERS received"), baru lanjut ke diagnosa detail di bawah — kemungkinan masalahnya di sisi NAT/Cloud node atau routing, bukan lagi di file interfaces.

Langkah Perbaikan (Detail)

1. Tes koneksi internet dasar
ping 8.8.8.8
Fungsi: mengirim paket ICMP ke IP publik untuk tes apakah ada jalur keluar sama sekali — tanpa melibatkan DNS (langsung ke IP, bukan nama domain).
Output: kalau lancar, muncul balasan 64 bytes from 8.8.8.8: icmp_seq=1 ttl=... time=...ms berulang. Kalau bermasalah, muncul Network is unreachable (routing) atau Request timeout (kemungkinan diblok firewall/DNS).
"Network is unreachable"Masalah di koneksi/routing — bukan DNS.
"timeout" sajaBaru kemungkinan masalah DNS/firewall.
2. Cek semua interface jaringan
ip addr show
Fungsi: sama seperti ip a — menampilkan semua interface beserta IP address yang sedang aktif, buat cek satu-satu mana yang bermasalah.
Output: interface sehat menampilkan baris inet 10.0.3.15/24. Kalau cuma ada inet6 fe80::... tanpa baris inet, itu tandanya belum dapat IPv4 dari DHCP.

Lihat interface ke arah internet (misalnya ens4). Kalau statusnya UP tapi cuma punya IPv6 (fe80::...) tanpa IPv4 → interface itu belum dapat IP dari DHCP.

3. Restart interface yang bermasalah
ifdown ens4 && ifup ens4
Fungsi: ifdown mematikan interface, ifup menyalakan lagi sesuai konfigurasi di /etc/network/interfaces — dipakai berurutan (&&) supaya interface benar-benar minta ulang IP dari awal ke DHCP server.
Output: biasanya tanpa output kalau sukses. Kalau ada masalah, muncul pesan error dari ifupdown (misalnya interface tidak dikenal, atau config syntax salah).

Ganti ens4 dengan nama interface kalian sendiri. Ini memaksa interface minta ulang IP ke DHCP server (biasanya NAT node di GNS3).

4. Pastikan proses DHCP berhasil

Setelah restart, harus muncul log seperti:

DHCPDISCOVER on ens4 to 255.255.255.255 port 67
DHCPOFFER of 192.168.140.63 from 192.168.140.1
DHCPACK of 192.168.140.63 from 192.168.140.1
bound to 192.168.140.63 -- renewal in 301 seconds.

Kalau log ini muncul → interface sudah dapat IP dengan benar.

5. Verifikasi ulang
ip route show
ping -c 3 8.8.8.8
ping -c 3 deb.debian.org
Fungsi ip route show: menampilkan tabel routing — cek apakah ada baris default via ... (gateway) yang dipakai untuk trafik keluar.
Fungsi ping -c 3: sama seperti ping biasa, tapi dibatasi 3 paket saja lalu berhenti otomatis (praktis buat tes cepat berulang).
Output: ip route show sehat menampilkan baris default via 192.168.x.x dev ens4. ping deb.debian.org yang sukses berarti DNS dan routing sama-sama sudah beres.

Semua harus berhasil (dapat reply, bukan unreachable).

6. Jalankan apt update lagi
apt update
Fungsi: refresh index paket dari repository Debian — tidak menginstall apa pun.
Output sukses: deretan baris Get:1 http://deb.debian.org/debian ... diakhiri Reading package lists... Done, tanpa baris "Temporary failure resolving".

Kalau semua tes di atas sudah oke, ini seharusnya jalan normal.

Kalau muncul warning IPv6 duplicate address, abaikan saja — itu cuma soal IPv6, tidak memengaruhi internet IPv4.
7. Kalau semua di atas sudah dicoba tapi masih error juga

Coba ganti tipe node di topologi GNS3: yang tadinya pakai Cloud, ganti ke NAT — atau sebaliknya kalau tadinya sudah NAT, coba ganti ke Cloud.

Kenapa ini kadang membantu: Cloud di GNS3 nge-bridge langsung ke interface fisik/virtual host kamu (butuh permission & interface host yang cocok), sedangkan NAT pakai NAT engine bawaan GNS3/libvirt yang punya DHCP sendiri. Kadang salah satu gagal connect ke internet gara-gara environment host (driver interface, permission, atau interface yang dipilih di Cloud salah), sementara yang satunya jalan normal — dua-duanya sebenarnya beda mekanisme walau tujuannya sama (kasih akses internet ke topologi).
Cara ganti: hapus node Cloud/NAT lama dari kanvas GNS3 (kabel ikut kehapus), tarik node pengganti dari panel kiri, sambungkan ulang ke Debian (ens4), lalu ulangi dari langkah ifdown/ifup atau restart networking.

Kalau setelah ganti ini masih error juga — ya sudah, sabar dulu 😄 kemungkinan ada yang lebih dalam di sisi environment/host, cek versi GNS3 & driver jaringan host.

Checklist Cepat untuk Kasus Serupa

  • Errornya beneran DNS, atau jangan-jangan "Network is unreachable" (routing)?
  • ip addr show — interface ke arah internet punya IPv4 (bukan cuma IPv6 link-local)?
  • ip route show — ada baris default via ...?
  • Interface pakai DHCP tapi gak dapat IP → coba ifdown <iface> && ifup <iface>
  • Kalau "No DHCPOFFERS received" → cek koneksi ke NAT node/Cloud node di topologi GNS3
  • Sudah semua dicoba tapi masih error → ganti tipe node Cloud ↔ NAT di topologi, lalu ulangi

Referensi Config yang Dipakai — dengan Koreksi Syntax

Perlu diperbaiki: di config asli, baris ens5 menulis address 192.168.1.1/24 sekaligus baris netmask 255.255.255.0 terpisah. Dua-duanya sama-sama menyatakan prefix — pakai salah satu saja, jangan digabung, supaya ifupdown tidak parse ganda.

Config asli (redundan)

auto lo
iface lo inet loopback

auto ens4
iface ens4 inet dhcp

auto ens5
iface ens5 inet static
        address 192.168.1.1/24
        netmask 255.255.255.0

Sesudah dirapikan (pilih satu gaya)

auto lo
iface lo inet loopback

auto ens4
iface ens4 inet dhcp

auto ens5
iface ens5 inet static
    address 192.168.1.1
    netmask 255.255.255.0

Atau kalau mau gaya CIDR ringkas, cukup satu baris address 192.168.1.1/24 tanpa baris netmask terpisah — jangan dua-duanya sekaligus.

Dokumen ini dibuat untuk dibagikan sebagai referensi — cek ulang tiap langkah dan sesuaikan IP/interface dengan environment masing-masing.
